学习笔记：网络、HTTP与结构化数据

一、网络角色与地址

1.1 客户端与服务端

  • 客户端发起请求，例如浏览器、curl。
  • 服务端监听地址与端口，接收请求、生成响应。
  • 二者是角色，可以位于同一台电脑。

本次实验角色示意：

Windows 浏览器或 WSL 中的 curl
              ↓
      127.0.0.1:8000 服务入口
              ↓
       Python HTTP 文件服务

这不是抓包验证后的完整 Windows—WSL 底层路径。服务运行在 WSL，Windows 浏览器能访问，不等于两者的网络命名空间完全相同。

1.2 地址、端口、协议与路径

项目 作用
IP 地址 网络通信中的地址
端口 区分服务入口
协议 规定通信内容如何组织和解释
路径 应用层请求的资源位置

端口能连接不代表协议匹配。不能用 SSH 工具打开 HTTP URL，并据此判断 HTTP 服务是否正常。

1.3 回环地址与执行位置

  • 127.0.0.1 是 IPv4 回环地址，::1 是 IPv6 回环地址。
  • localhost 是主机名，可能解析到上述地址。
  • 回环地址首先指向当前网络环境自身；Windows 与 WSL 之间还可能涉及本地转发。
  • 命令在哪里执行，通常就操作哪里的文件、进程和网络环境。

1.4 DNS 与 TCP

  • DNS 负责名称解析，不负责解释 URL 路径。
  • TCP 提供双向、有序的字节流。
  • TCP 连接成功不等于 HTTP 资源存在，也不等于业务目标完成。

二、URL 的组成

http://127.0.0.1:8000/search?q=hello&limit=5#results
部分 内容
协议方案 http
主机 127.0.0.1
端口 8000
路径 /search
查询字符串 q=hello&limit=5
片段 results

关键点：

  1. #results 片段不会自动包含在 HTTP 请求目标中。
  2. 查询参数首先是文本，服务端按规则解析、验证和转换。
  3. URL 路径不一定直接对应磁盘路径。
  4. Python 静态服务中的网站根路径 / 对应配置的服务目录，不是 Linux 根目录。

三、HTTP 请求与响应

以下是 HTTP/1.x 的基本展示形式，不能直接当作所有 HTTP 版本的线上格式。

3.1 HTTP 请求结构

GET /hello.txt HTTP/1.1
Host: 127.0.0.1:8000

基本结构：请求行 → 请求头 → 空行 → 可选正文。

请求行包含方法、请求目标、协议版本。

3.2 HTTP 响应结构

HTTP/1.0 200 OK
Content-Type: text/plain
Content-Length: 5


HELLO

基本结构：状态行 → 响应头 → 空行 → 正文。

  • 200 是状态码，OK 是状态说明。
  • HELLO 是正文。
  • Content-Length: 5 声明正文长5字节，不包含响应头。
  • 状态说明与正文中的文字可能相同，必须按位置区分。

3.3 连接、响应与业务成功

层次 判断内容
连接与传输 是否连接并取得响应
HTTP 状态 服务端报告成功、重定向还是错误
正文与业务 内容是否是需要的资源

200、curl 退出0、文件成功保存，都不能单独证明目标内容正确。

例如要下载 ZIP，实际保存的可能是返回200的登录页面。该判断的对话检查已通过。

四、GET、POST、表单与 JSON

4.1 GET 与 POST

  • GET 常用于获取资源，POST 常用于提交数据。
  • POST 可以同时携带查询参数和正文。
  • POST 不会自动加密，传输加密通常涉及 HTTPS/TLS。
  • 方法名不能独立证明权限或数据可信。

4.2 表单编码

Content-Type: application/x-www-form-urlencoded

name=Li&message=hello

以上正文全部为 ASCII，共21字节。在这种表单编码规则中，+ 常表示空格，%2B 表示加号本身；不能推广到所有字符串场景。

长度勘误：user=Li&password=abc 为19字节，不是20字节。长度应按实际正文计算，额外换行也会改变结果。

4.3 JSON 数据结构

Content-Type: application/json

JSON 有对象、数组、字符串、数字、布尔值、null 等值类型。

  • 对象键和字符串使用双引号。
  • 数字 5 与字符串 "5" 不同。
  • JSON 语法合法不等于业务内容有效。
  • Content-Type 是声明，不会自动修正正文。
  • 客户端把 "admin": false 改为 true，不代表服务端应该授予管理员权限。

五、Cookie、会话与 Authorization

5.1 Cookie 与会话

服务端响应 Set-Cookie
        ↓
浏览器按规则保存
        ↓
后续请求携带 Cookie

Cookie 不一定用于登录，也可保存偏好。常见会话模型是浏览器携带会话标识，服务端据此查会话记录并验证状态。

属性 边界
HttpOnly 限制常规页面脚本读取，不是加密
Secure 通常要求通过安全连接发送
SameSite 影响跨站请求中的发送行为
Path 限制发送范围，不是可靠授权边界

5.2 Authorization 请求头

Authorization: Bearer 示例令牌

服务端仍需检查令牌有效性与权限。

  • 认证：你是谁。
  • 授权：你能做什么。

携带字段、Cookie 或令牌，不等于通过验证。

六、重定向

6.1 重定向的基本过程

请求地址 A
    ↓
响应重定向状态与 Location
    ↓
客户端决定是否跟随
    ↓
另发请求到地址 B
  • Location 可以是相对地址。
  • 重定向响应没有正文也可引导跳转。
  • 最终页面不一定来自第一份响应。
  • 两次 HTTP 请求不等于必然建立两条 TCP 连接。

6.2 重定向后的请求方法

  • 303 常引导客户端以 GET 获取另一个资源。
  • 307/308 保持方法与正文。
  • 301/302 在常见客户端处理中可能把 POST 改为 GET，不能认为所有跳转行为都相同。

6.3 浏览器与 curl 的重定向处理

浏览器通常自动跟随常见重定向；curl 默认不跟随，-L 用于跟随。

但 curl 加 -L 不等于完整模拟浏览器的缓存、脚本、页面加载和登录行为。

curl --noproxy '*' --http1.1 -sS -i \
  'http://127.0.0.1:8000/jump-demo'

curl --noproxy '*' --http1.1 -sS -i -L \
  'http://127.0.0.1:8000/jump-demo'

预期后一条显示先后两组响应头，再显示最终正文；不是一个响应拥有两条状态行。

七、浏览器网络面板与请求复制

7.1 网络面板中的请求信息

  • 打开网络面板后再访问或刷新。
  • 禁用缓存通常仅在开发者工具打开时生效。
  • 保留日志有利于跨导航观察，也可能混入旧记录。
  • 对照前清空记录，核对选中的请求。
  • 开发者工具是解析后的展示，不是原始网络字节的完整副本。

7.2 将请求复制为 curl 命令

curl --url 'http://127.0.0.1:8000/hello.txt' \
  -H 'Accept: text/html'
  • --url 指定地址，-H 设置请求头，可重复。
  • 没有改变方法或提交正文的选项时，本例默认 GET。
  • Bash 行尾反斜杠用于续行，后面不能再加空格。
  • 分享复制命令前应检查并脱敏 Cookie、Authorization 等敏感信息。

已分析复制出的请求，未提供该完整命令再次执行的输出。

7.3 常见请求头与含义

请求头 作用或限制
Accept 内容类型偏好，q 可表达相对偏好
Accept-Language 语言偏好
Accept-Encoding 支持的内容编码，不证明本次响应实际压缩
User-Agent、sec-ch-ua* 客户端自报信息，不是身份凭据
Sec-Fetch-* 浏览器请求上下文，手工客户端可设置
Cache-Control: no-cache 不简单等于禁止保存，通常涉及复用前验证
Upgrade-Insecure-Requests 不会把当前 HTTP 自动变成加密通信
Connection: keep-alive 不保证服务端保持连接，也不证明已经复用

实际404响应含 Connection: close。关于“能否只凭请求 keep-alive 认定连接保持或复用”的检查已答对：不能。

八、数据包、TCP 字节流与 HTTP 文件

数据包
  ↓ 按连接、方向、序列等处理
TCP 字节流
  ↓ 按协议识别消息和正文边界
HTTP 消息
  ↓ 提取正文，必要时处理内容编码
文件或应用数据

基础结论：

  1. 一个包不等于一条 HTTP 消息，一条消息可能跨多个包。
  2. TCP 不保留应用每次发送的边界。
  3. 同一连接可能承载多次 HTTP 交互。
  4. 不能把抓包列表中的负载不加处理地直接拼成文件。
  5. 跟踪 TCP 流不等于导出 HTTP 对象。
  6. 字符编码、内容压缩、传输分块和 TLS 加密不是同一层。
  7. HTTPS 的外部抓包不默认显示路径、Cookie 和正文。
  8. 浏览器作为通信端点能显示内容，不代表外部抓包也可直接看见明文。

九、常见排错与操作注意事项

9.1 Shell 变量的终端作用范围

历史执行：

printf '服务目录：%s\n' "$practice_dir"

输出为空只说明该 Shell 的变量为空或未设置，不证明服务已停或目录已删。

此时 "$practice_dir/jump-demo" 将变为 /jump-demo，不能继续盲目创建或覆盖文件。服务目录应核对真实启动命令，不猜临时目录名。

9.2 前台服务与文件路径

  • 服务占据前台时，不要继续在其中输入 Shell 命令。
  • 可另开终端，或按 Ctrl+C 停止当前前台服务。
  • 看到启动提示仍需访问验证。
  • Address already in use 表示地址或端口被占用，不应反复重复启动。
  • 相对服务目录依赖启动位置；完整路径可减少目录解析错误。
  • 404 说明收到了 HTTP 响应，不等于服务没启动。
  • 所有历史临时目录都不能当作当前仍存在的固定路径。

十、网络请求的判断原则

收到响应不等于资源存在；HTTP 成功不等于正文正确；保存成功不等于格式、来源或安全性得到证明。

客户端声明不等于可信身份；状态码、退出码、正文内容应分别核对。
