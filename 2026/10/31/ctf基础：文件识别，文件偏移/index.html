ctf基础：文件识别，文件偏移

学习笔记：文件识别、字节观察与偏移

一、文件名、实际内容与工具识别

1. 三种信息要分开看

信息 观察对象 能说明什么
扩展名 文件名的一部分 名称声称的类型
真实字节 文件实际保存的数据 分析格式与结构的直接依据
工具识别结果 工具根据规则作出的判断 工具认为它像什么

**修改后缀不会转换格式。**把 ZIP 改名为 .jpg，内容仍然是原来的 ZIP 字节。

file 的判断也不是最终裁决，需要结合字节、结构和其他工具验证。

2. 文件签名或魔数

不少格式在约定位置包含特定字节：

格式 常见起始字节，按十六进制显示
PNG 89 50 4E 47 0D 0A 1A 0A
JPEG FF D8 FF
GIF 47 49 46 38 37 61 或 47 49 46 38 39 61
ELF 7F 45 4C 46
ZIP 常见为 50 4B 03 04，也存在其他情况

注意：

  • 这里显示的是真实字节的十六进制表示，不是文件中保存了同样的 Hex 文本。
  • 发现签名，只能先说明存在格式线索。
  • 不能仅凭签名保证文件完整、能正常解析或内容安全。

二、三个基本观察工具

工具 主要用途
file 根据规则识别文件类型
strings 搜索符合条件的可打印字符片段
xxd 查看真实字节和文件偏移

1. file：识别类型及其局限

file 文件名
file -L 文件名

-L 表示跟随符号链接检查目标。

file 会使用文件系统信息、内容特征规则和文本特征等进行判断，不只是看扩展名，也不只是检查开头四字节。

可能出现的情况：

  • 格式较新、少见或特征不足，无法具体识别。
  • 文件损坏、截断，识别不完整。
  • 识别外层结构，但没有报告全部内嵌数据。
  • 某些人工构造的特征造成误判。
  • 能识别某些带额外前缀的格式，但不保证识别所有情况。

如果输出：

data

只表示没有得到更具体的识别结果，不等于已经加密、没有结构或文件损坏。

2. strings：查找可打印片段

strings -a 文件名
strings -a -n 3 文件名
strings -a -t x 文件名
选项 含义
-a 扫描整个文件
-n 3 最短字符串长度改为三个字符
-t x 用十六进制显示字符串的起始文件偏移

本次使用环境中的默认最短长度为四个字符。

注意：

  • 默认没有显示某段文字，不代表文件里没有它。
  • strings 不理解字符串的用途。
  • 找到 SECRET=42，不证明它是真密码或程序一定会使用它。
  • 压缩、加密或某些编码下的文本，不一定能直接找到。

3. xxd：查看字节与偏移

xxd -g 1 文件名
xxd -g 1 -l 32 文件名
xxd -g 1 -s 0x100 -l 16 文件名
选项 含义
-g 1 每组显示一个字节
-l 32 最多显示三十二个字节
-s 0x100 从文件偏移 0x100 开始

输出示例：

00000000: 00 01 48 45 4c 4c 4f 00 ff 53 45 43 52 45 54 3d  ..HELLO..SECRET=
00000010: 34 32 00 45 4e 44 0a                             42.END.
  • 左列：这一行第一个字节的文件偏移，按十六进制显示。
  • 中间：真实字节的十六进制表示。
  • 右列：可打印字符预览。

**右侧的点不一定是真实句点。**许多不可打印字节都会显示为 .；真实句点字符的 ASCII 字节是 2E。

00000010 是十六进制 0x10，等于十进制 16，不是十进制的 10。

三、文件偏移与 dd 提取

1. 文件偏移从零开始

字节：41 42 43 44
偏移： 0  1  2  3
字符： A  B  C  D

偏移 2 对应第三个字节 43。

某个位置的一个字节，与从该位置开始的一段数据，不是同一个问题。

2. dd 的基本用法

dd 是按块复制数据、支持部分转换的工具。它不理解 ZIP、PNG 或 ELF 的格式结构。

dd if=输入文件 of=输出文件 bs=1 skip=9 count=9 status=none
参数 含义
if= 输入文件；省略时通常从标准输入读取
of= 输出文件
bs=1 每块一个字节
skip=9 跳过九个输入块
count=9 最多复制九个输入块
status=none 隐藏常规统计信息，错误仍会报告

本节用 bs=1，使 skip、count 的块数与字节数对应。

例如：

bs=4 skip=2 count=3

表示跳过 8 字节，最多复制 12 字节。

没有设置 count 时，会复制到输入结束，包括可能存在的尾部额外数据。

3. 提取后偏移重新计算

原样、连续提取时：

新文件偏移=原文件偏移-提取起点

例如：从原文件偏移 12 开始提取，某字节原偏移为 20，新文件中该字节的偏移为 20-12=8。

只有提取起点对应的新偏移是零，不是所有目标字节都变成零。

4. 提取后必须检查

file 输出文件
xxd -g 1 输出文件
wc -c < 输出文件

分别检查类型、内容和实际字节数。输入不足时，实际复制量可能少于预期。

四、原件、副本、哈希与单字节修改

1. 建立工作副本并比较

cp -i 原件 工作副本
sha256sum 原件 工作副本

普通文件的 SHA-256 针对内容字节，不包含文件名。因此内容相同、名字不同，摘要仍相同。

  • 摘要不同：内容不同。
  • 安全哈希相同：可以极有把握地认为内容一致。
  • 摘要不能告诉我们改在何处、改了多少字节。
  • 哈希匹配不证明内容安全或来源可信。

2. 保存基准并校验

在 ~/env-practice 中：

sha256sum work/byte-observe-01/sample.jpg > work/byte-observe-01/original.sha256
sha256sum -c work/byte-observe-01/original.sha256

输出：

work/byte-observe-01/sample.jpg: OK

表示当前原件与基准记录匹配。

注意：

  • 校验时，记录中的相对路径按当前工作目录解析。
  • 不要修改文件后重新覆盖基准，再宣称“文件没变”。
  • 基准记录本身也需要可信、妥善保留。

3. 修改已有文件的指定字节

本次只修改工作副本的偏移 2，将 48（H）改为 68（h）：

printf '\x68' | dd of=work/byte-observe-01/sample-work.bin bs=1 seek=2 count=1 conv=notrunc status=none
参数 含义
seek=2 从输出文件的字节偏移 2 处开始写入
conv=notrunc 不截断已有输出文件，保留其他内容

区别：skip 跳过输入，seek 定位输出。

输出路径不能误写成原件；修改已有文件时不能漏掉本例所需的 conv=notrunc。

4. 验证“改对了”与“只改了这里”

xxd -g 1 工作副本
cmp -l 原件 工作副本
wc -c 原件 工作副本
  • 看目标位置：确认改对了。
  • 比较整个文件：排除其他位置变化。
  • 比较长度：排除插入、截短等问题。

本次 GNU cmp -l 的预期输出：

3 110 150

含义：

  • 3：第三个字节，从一计数，对应文件偏移 2。
  • 110、150：两个字节值，按八进制显示。
  • 分别对应十六进制 48、68。

5. 修改记录模板

修改对象：
文件偏移及其进制：
原字节：
新字节：
修改目的与依据：
验证结果：
原件基准校验结果：

本次单字节修改是教学练习，不等于完成了一次有格式依据的文件修复。

六、ELF 基础：头、节与段

1. 三种结构

结构 作用
ELF 头 描述位数、端序、架构、入口及其他表的位置等
程序头表 描述段及加载相关信息
节头表 描述按用途组织的节
  • 节偏向内容用途，例如代码、数据、符号信息。
  • 段偏向程序加载布局。
  • 一个段可以包含多个节。
  • 并非所有节都需要加载进内存。
  • 表中的记录不是它所描述的内容本身。

2. 观察命令

file -L /bin/ls
readelf -h /bin/ls
readelf -lW /bin/ls
  • -h：ELF 头。
  • -l：程序头表。
  • -W：宽格式显示。

4. LOAD 关键字段

字段 含义
Offset 段的文件起始偏移
VirtAddr ELF 中记录的段起始虚拟地址
FileSiz 段在文件中的内容大小
MemSiz 段所需的内存大小
Flg 读、写、执行权限

权限：R 为读，W 为写，E 为执行。

若 MemSiz 大于 FileSiz，可加载段中多出的区域在加载时补零，常与 .bss 等有关。

这部分内存没有该段中的对应文件字节，不能直接从原文件提取。

七、文件偏移、虚拟地址与运行时地址

1. 概念区别

概念 含义
文件偏移 相对文件开头的字节位置
段内偏移 相对该段起点的距离
虚拟地址 进程虚拟地址空间中的位置
运行时地址 本次运行实际使用的位置；普通 Linux 用户程序中通常仍是虚拟地址

不同进程使用相同虚拟地址，不一定对应同一块物理内存；也可能因共享映射而对应同一块。

ASLR 等机制可能使加载位置随运行变化。

2. 文件偏移与 ELF 虚拟地址换算

确认目标位于某个可加载段的文件内容范围内后：

段内偏移=文件偏移-段的文件起始偏移
ELF 虚拟地址=段的 VirtAddr+段内偏移

若已知适用的加载偏移：

运行时虚拟地址=加载偏移+ELF 虚拟地址

不能对整个文件任意套用，必须先确认所属段。

八、磁盘扇区与分区坐标

1. 扇区编号与字节偏移

LBA 可在本节理解为逻辑扇区编号，通常从零开始。

逻辑扇区大小可能是 512 或 4096 字节等，必须确认。逻辑扇区大小与物理扇区大小也可能不同。

整盘字节偏移=LBA×每扇区字节数+扇区内偏移

例：每扇区 512 字节，LBA 10 内偏移 8：

10×512+8=5128

2. 分区起点

某分区从 LBA 2048 开始，每扇区 512 字节；目标位于分区内部字节偏移 1024：

2048×512+1024=1049600

必须说明偏移相对整盘、分区还是文件。

3. 换算边界

  • 文件可能在磁盘上分散存放。
  • 不能直接用“分区起点＋文件内部偏移”得到文件字节的整盘位置。
  • 需要文件系统分配信息。
  • 扇区编号乘大小可直接对应镜像偏移，需要原始字节布局等适用条件；带封装的镜像不能机械套用。
  • 本次只做概念与计算，没有操作真实磁盘设备。

九、EVM 存储槽坐标

本节“存储槽”指 EVM 合约持久存储的槽，不是磁盘扇区。

1. 基本概念

每个槽保存：

256 位=32 字节

槽编号是一个 256 位的键。概念上未写入的槽读取为零，不代表所有槽都预先分配了物理空间。

槽编号不是文件偏移，不能无依据地乘以 32 后用 dd 提取。

2. 变量可能共用一个槽

在普通、没有继承等额外因素的顺序布局示例中：

uint128 a;
uint128 b;
uint256 c;
变量 位置
a 槽 0 的低 16 字节
b 槽 0 的高 16 字节
c 槽 1

按高位在左、低位在右展示槽值：

[ b：高 16 字节 ][ a：低 16 字节 ]

所以定位打包变量需要：

  • 槽编号。
  • 槽内位置。
  • 变量长度。
