ctf基础：C，汇编

发表于2026-11-07|更新于2026-11-07

C，汇编

一、C 类型、对象与字节

1.1 C 对象的含义

C 中的“对象”可以理解为一块用于存放值的存储区域，不是面向对象语言中“类的实例”那个特定含义。

例如：

int count = 3;
char input[32];
  • count 是一个 int 对象。
  • input 是一个数组对象。
  • 数组中的每个元素也是对象。

分析一个对象时，要分别考虑：

  1. 类型：如何解释其值、允许进行哪些操作。
  2. 大小：占多少个 C 字节。
  3. 地址：存储位置在哪里。
  4. 生命周期：什么时候存在，什么时候失效。
  5. 边界：允许访问的范围。

逆向分析中，看到四字节内存不等于就能断定它是 int；还要结合指令、用途和数据流判断。

1.2 C 字节与 CHAR_BIT

C 规定：

sizeof(char) == 1

但这里的 1 表示一个 C 字节，不直接表示八位。

每个 C 字节包含多少位，由 <limits.h> 中的 CHAR_BIT 给出。

当前 Linux x86-64 环境通常满足：

CHAR_BIT == 8

因此，本笔记中的实际字节示例按八位字节解释。

不能把“当前平台每字节八位”写成“C 标准规定每字节只能八位”。

1.3 常见类型大小与平台差异

当前 Linux x86-64 常见的 LP64 数据模型：

类型 常见大小
char 1 字节
short 2 字节
int 4 字节
long 8 字节
long long 8 字节
普通对象指针 8 字节

Windows x64 常用 LLP64 模型，其中 long 通常是四字节。

所以：

同样是64位系统，不代表所有整数类型都与指针一样宽，也不代表不同操作系统的类型大小相同。

char、signed char、unsigned char 是不同类型；普通 char 的有符号性由实现决定。

1.4 sizeof 的含义与用法

sizeof 给出对象或类型占用的 C 字节数，结果类型是 size_t。

int values[5];
int *p = values;

在当前环境中：

sizeof(values)   // 20：整个数组
sizeof(p)        // 8：指针对象
sizeof(*p)       // 4：一个 int

计算真实数组的元素数量：

sizeof(values) / sizeof(values[0])

前提是这里的 values 仍然是数组，不是已经转换后的指针。

打印 sizeof 的结果应使用匹配的格式：

printf("%zu\n", sizeof(values));

1.5 固定宽度整数类型

<stdint.h> 提供：

uint8_t
int32_t
uint64_t

这些精确宽度类型只有在实现支持对应表示时才提供。

在当前环境中，它们适合表达：

  • 明确宽度的二进制字段；
  • 字节变换；
  • 位掩码；
  • 协议与文件结构中的整数。

但固定宽度类型不会取消整数提升。例如 uint8_t 参与加法时，仍可能先提升为 int。

二、数组、指针、字符串与生命周期

2.1 数组不是指针

char input[32];
char *p = input;

两者不同：

  • input 是包含32个字符元素的数组。
  • p 是保存地址的指针对象。

数组名在许多表达式中会转换为指向首元素的指针，因此看起来经常能当指针使用。

但：

sizeof(input)  // 数组整体大小
sizeof(p)      // 指针大小

结果不同。

数组对象也不能像普通指针变量那样重新赋值：

p = other;       // 类型兼容时可以
input = other;   // 不允许数组整体这样赋值

2.2 地址与解引用

int value = 42;
int *p = &value;
  • &value：取得对象地址。
  • p：保存这个地址。
  • *p：访问该地址所指的 int 对象。
*p = 7;

修改的是 value。

必须保证指针：

  • 指向仍然有效的对象；
  • 满足相应类型的访问要求；
  • 没有越过允许边界；
  • 不是未初始化的随机值。

“某个地址能显示出字节”不自动意味着程序可以按任意类型合法访问它。

2.3 指针运算以元素大小为单位

int values[4];
int *p = values;

p + 1

前进一个 int，当前平台通常是四字节，而不是一字节。

数组下标的定义关系是：

p[i]

等价于：

*(p + i)

对四元素数组：

  • p + 0 到 p + 3 指向元素。
  • p + 4 可以作为尾后指针形成。
  • 尾后指针不能被解引用。

允许形成一个地址，不等于允许读取那个地址。

2.4 字符串长度、容量与终止零

char text[8] = "cat";

其字节开头为：

63 61 74 00 00 00 00 00
 c  a  t
概念 本例结果
数组容量 8 字节
字符串长度 3 字节
存放 "cat" 至少需要 4 字节 
sizeof(text)  // 8
strlen(text)  // 3

其中：

  • '\0' 是数值为零的字符，作为字符串终止标记。
  • '0' 是字符零，当前 ASCII 兼容编码中为 0x30。
  • '\n' 是换行符，当前环境中为 0x0a。

三者不能混淆。

strlen 不接收容量参数，只会寻找第一个终止零。如果对象范围内没有有效终止零，继续扫描可能造成越界读取。

2.5 数组参数与容量信息

void inspect(char buf[32])
{
    printf("%zu\n", sizeof(buf));
}

函数参数中的数组声明会调整成指针参数。因此上面的 sizeof(buf) 是指针大小，不是32。

应显式传入容量：

void inspect(char *buf, size_t capacity)
{
    /* 使用 capacity 判断允许访问的范围 */
}

函数知道指针值，不代表它自动知道指向对象有多大。

2.6 fgets 与输入边界

char input[32];


if (fgets(input, sizeof input, stdin) == NULL) {
    return 1;
}

本例中，成功读取时：

  • 最多存放31个输入字节；
  • 再添加一个终止零；
  • 如果读到换行且空间足够，换行会被保留。

键入 cat 后回车，常见内容为：

63 61 74 0a 00

去掉换行：

input[strcspn(input, "\n")] = '\0';

strcspn 返回从开头起连续不包含指定字符的长度。这里用于找到第一个换行的位置。

如果没有换行，它返回当前字符串长度，赋值位置就是已有的终止零。

注意两个边界：

  1. 读入成功不等于已经读完整条输入。 过长输入可能只读入一部分。
  2. 容量安全不等于业务正确。 截断后的内容是否允许参与校验，仍需要程序设计决定。

2.7 strcmp 与 memcmp

strcmp

strcmp(a, b)

比较两个终止零字符串。保证返回：

  • 负数：第一个字符串小于第二个；
  • 零：相等；
  • 正数：第一个字符串大于第二个。

不能假定只返回 -1、0、1。

memcmp

memcmp(a, b, n)

比较指定的 n 个字节：

  • 不会因中途遇到终止零就停止；
  • 要求双方相应范围都可访问；
  • 适合二进制数据比较。

例如两块数据：

41 00 42
41 00 43

若作为字符串比较，终止零后的差异不参与比较；若用 memcmp 比较三个字节，则能发现不同。

2.8 内存复制不自动处理字符串语义

memcpy(dst, src, n);

只复制 n 个字节：

  • 不自动追加终止零；
  • 不自动检查目标容量；
  • 源、目标范围必须有效；
  • 两个范围不能重叠。

可能重叠时使用 memmove。

因此，“复制完成”不等于“得到一个有效 C 字符串”。

2.9 生命周期与悬空指针

错误示例：

char *bad(void)
{
    char buf[16];
    return buf;
}

函数返回后，局部数组生命周期结束。

即使原地址上暂时还保留旧字节，指针也不能因此继续合法使用。

类似问题还包括：

free(p);

之后继续访问原对象。变量 p 仍可能保留旧地址，但所指对象的生命周期已经结束。

地址数值还在，不等于对象还在。

2.10 常见存储区域与限制

对象 常见实现位置 生命周期
普通局部变量 栈或寄存器 通常与所在块或调用相关
动态分配对象 堆 分配到释放
全局与静态对象 数据区域 通常贯穿程序执行
字符串字面量 常见于只读区域 静态存储期

这些是常见实现，不是“所有局部变量都必须占一个栈槽”。

字符串字面量不应修改：

char *p = "cat";
p[0] = 'b';       // 未定义行为

而：

char p[] = "cat";
p[0] = 'b';       // 修改可写数组

二者不同。

三、C 整数运算与类型转换规则

3.1 整数提升

unsigned char a = 250;
unsigned char b = 10;


int result = a + b;

当前平台的 int 能表示 unsigned char 的全部值，因此两个操作数先提升为 int，相加得到260。

若写成：

unsigned char result = a + b;

仍然是先得到260，再转换到八位无符号类型，得到4。

关键过程：

原始类型 → 整数提升 → 表达式计算 → 保存时转换

不能直接说“两个八位数，所以加法一定在八位里执行”。

3.2 有符号与无符号混合比较

int a = -1;
unsigned int b = 1;


int result = a < b;

当前平台上，比较时 a 会转换为 unsigned int，成为该类型最大值，所以结果为假。

分析方法：

  1. 确认原始类型。
  2. 做整数提升。
  3. 判断通常算术转换后的共同类型。
  4. 再进行运算或比较。

数学大小关系不能跳过语言的类型转换规则。

3.3 无符号回绕

对于 $n$ 位无符号整数，运算结果按模 $2^n$ 处理：

$$ r=(a+b)\bmod 2^n $$

当前八位无符号类型中：

$$ 255+1\equiv 0\pmod{256} $$

但如果操作数先提升成 int，就要先考虑提升后的计算，再考虑保存时转换。

3.4 有符号溢出

int value = INT_MAX;
value = value + 1;

C17 中，有符号算术溢出属于未定义行为。

不能因为某次机器运行得到最小负数，就认为标准保证回绕。

编译器可以依据“有效程序不会发生有符号溢出”进行优化，因此调试版观察到的现象，不一定能推广到其他优化设置。

3.5 窄化转换与符号扩展

转为无符号窄类型

超出范围时，按目标类型的模数转换。

转为有符号类型

若原值不可表示，C17 规定结果为实现定义的，或者产生实现定义的信号；不能统一当成无符号截断规则。

扩展到更宽类型

  • 零扩展：高位补零。
  • 符号扩展：按符号位扩展。

例如八位模式：

11111110

按八位无符号解释为254；按当前常见八位补码有符号解释为−2。

扩展方式不同，最终宽整数的值不同。

逆向时可关注：

movzx   ; 零扩展
movsx   ; 符号扩展

但仍要结合源操作数宽度和上下文判断原始类型。

3.6 移位规则

对于：

x << k
x >> k

至少检查：

  1. x 提升后的类型和位宽；
  2. k 是否为负；
  3. k 是否小于该位宽；
  4. 左操作数是否为负；
  5. 左移是否符合可表示性要求。

C17 中：

  • 移位次数为负，或不小于提升后左操作数的位宽：未定义行为。
  • 负有符号数左移：未定义行为。
  • 非负有符号数右移：相当于除以相应的二次幂并取整数部分。
  • 负有符号数右移：结果具有实现定义性质。
  • 无符号类型更适合表达明确的位操作。

机器指令对移位次数的处理规则，不等于 C 语言允许任意移位次数。

3.7 未定义行为与崩溃

未定义行为不等于“一定报错”。

例如：

  • 有符号溢出；
  • 越界访问；
  • 使用生命周期已结束的对象；
  • 修改字符串字面量；
  • 非法移位。

可能表现为：

  • 暂时得到预期结果；
  • 输出异常；
  • 崩溃；
  • 优化后出现难以直觉解释的行为。

因此：

不崩溃不能证明程序没有越界，也不能证明代码符合 C 规则。

四、从 C 到机器代码：编译、寄存器与指令

4.1 编译过程

可以粗略分为：

预处理 → 编译 → 汇编 → 链接
  • 预处理：处理头文件包含、宏与条件编译。
  • 编译：进行语义分析、优化和代码生成。
  • 汇编：生成目标文件中的机器代码及相关信息。
  • 链接：组合目标文件、处理符号引用，形成最终程序或库。

历史样本使用：

gcc -std=c17 -Wall -Wextra -g -O0 check.c -o check

参数含义：

参数 作用
-std=c17 指定 C17 语言模式
-Wall -Wextra 开启常用警告
-g 生成调试信息
-O0 不启用常规优化，便于入门调试
-o check 指定输出名称

-g 不等于把原始源码文本完整放进程序；调试信息可包含源码文件名、行号、类型和变量位置等信息。

-O0 也不保证一行 C 对应一条指令。

4.2 寄存器宽度

以 rax 为例：

名称 访问宽度
rax 64位
eax 32位
ax 16位
al 低8位

x86-64 中：

mov eax, 1

会将 rax 的高32位清零。

而：

mov al, 1

只更新低8位。

这会影响“某个寄存器现在是否完整代表一个零或一”的判断。

常见布尔转换：

sete  al
movzx eax, al

第一条只设置 al，第二条将其零扩展为完整的32位结果。

4.3 内存操作数

Intel 语法中：

mov eax, DWORD PTR [rbp-0x34]

含义是从计算出的地址读取四字节数据，放进 eax。

常见宽度：

标记 大小
BYTE PTR 1字节
WORD PTR 2字节
DWORD PTR 4字节
QWORD PTR 8字节

一般有效地址可包含：

基址 + 索引 × 比例 + 位移

比例通常可为1、2、4、8。

例如：

mov eax, DWORD PTR [rdi+rcx*4]

若 rdi 指向 int 数组开头，可能是在读取第 rcx 个元素。但“可能”还需由数据流支持，不能只看形式就断言类型。

4.4 mov 与 lea

mov rax, QWORD PTR [rbp-0x30]

读取内存内容。

lea rax, [rbp-0x30]

计算地址，不读取该地址的内容。

后者常对应：

&local

或数组首地址。

lea 还可用于整数计算：

lea eax, [rdi+rdi*4]

得到五倍的低32位结果。

lea 不访问方括号所表示的内存，也不像普通算术指令那样更新算术标志位。

4.5 cmp、test 与标志位

cmp eax, 0

按减法结果设置标志位，但不保存减法结果。

test eax, eax

按位与后设置标志位，也不保存结果，常用于检查是否为零。

常见标志位：

  • ZF：结果是否为零。
  • SF：结果最高位。
  • CF：无符号进位或借位相关。
  • OF：有符号溢出相关。

不是所有指令都以相同方式修改这些标志位。读分支时，要找到真正产生该分支所依赖标志位的指令。

4.6 有符号与无符号跳转

关系 有符号 无符号
小于 jl jb
小于等于 jle jbe
大于 jg ja
大于等于 jge jae

相等比较常见：

je / jz
jne / jnz

je 与 jz 是同一个条件的不同名字。

例如：

cmp edi, 10
ja  reject

表达无符号“大于10”。

如果 edi 的位模式为 0xffffffff，按无符号解释是很大的正数，因此会跳转。不能按有符号的−1来解释 ja。

4.7 setcc：把条件变成数值

cmp eax, 0
sete al
movzx eax, al

含义：

  1. 比较原来的 eax 与零；
  2. 相等则 al=1，不相等则 al=0；
  3. 将该字节零扩展为整数。

这常对应：

return value == 0;

条件既可以控制跳转，也可以被转换为零或一的数据结果。

五、函数调用、栈帧与返回值

5.1 Linux x86-64 System V 参数约定

常见整数或指针参数依次使用：

rdi、rsi、rdx、rcx、r8、r9

例如：

strcmp(input, "cat");

调用前重点看：

rdi → input
rsi → "cat"

例如：

fgets(input, 32, stdin);

调用前重点看：

rdi → 缓冲区
esi → 容量32
rdx → 输入流

这只是常见整数／指针参数的入门规则。浮点参数、聚合类型和更多参数还涉及其他规则。

5.2 返回值与寄存器宽度

常见整数或指针返回值使用 rax 或其低位部分：

  • 返回 int：通常关注 eax。
  • 返回普通指针：通常关注 rax。

strcmp 返回 int。历史调试用：

print /d $eax

观察它的有符号十进制返回值。

不能直接把整个 rax 按64位有符号数读取，就假定得到相同解释；对于 int 返回值，上半部分不是判断其符号的依据。

5.3 调用者保存与被调用者保存

System V 下，常见被调用者保存寄存器包括：

rbx、rbp、r12、r13、r14、r15

若函数使用并改变它们，需要在返回前恢复约定要求的值。

rax、参数寄存器等通常属于调用者需要考虑保全的寄存器。

因此：

调用一个函数后，不能假定调用前的参数寄存器仍保持原值。

逆向跟踪数据时，跨越 call 要检查数据究竟保存在寄存器、栈槽还是其他对象中。

5.4 call 与 ret

对于普通近调用：

call target

主要做两件事：

  1. 保存返回地址，即调用指令之后的位置；
  2. 转到目标函数。
ret

从栈中取得返回地址并转回。

call 不负责自动保存所有寄存器，也不负责自动给所有参数安排存储空间。

5.5 典型栈帧

未优化代码常见：

push rbp
mov  rbp, rsp
sub  rsp, 0x40

可以理解为：

  1. 保存旧 rbp；
  2. 让 rbp 成为当前帧的参考位置；
  3. 下调 rsp，预留局部存储等空间。

在这种特定栈帧形式下，常见关系是：

[rbp+8]  返回地址
[rbp]    保存的旧 rbp
[rbp-…]  局部存储

不能把这个布局推广到所有函数：

  • 优化后可能省略帧指针；
  • 叶函数可能不建立类似栈帧；
  • 局部变量可能在寄存器中；
  • 预留空间还包含对齐和临时数据。

尾部：

leave
ret

常用于撤销该类栈帧并返回。

5.6 栈对齐

普通 System V x86-64 调用中，调用者通常使栈在执行 call 前满足16字节对齐。

call 再压入八字节返回地址，因此函数入口处通常满足：

$$ (\mathrm{rsp}+8)\bmod 16=0 $$

分析栈空间时，对齐填充也是原因之一，不能把所有预留字节都认定为用户数组。

5.7 函数调用不等于系统调用

Linux x86-64 系统调用通常使用：

系统调用号：rax
参数：rdi、rsi、rdx、r10、r8、r9

第4个参数是 r10，而普通函数调用的第4个常见整数参数是 rcx。

调用 libc 函数：

puts("hello");

不等于程序直接执行一个同名系统调用。库函数可能先处理缓冲等逻辑，再间接使用系统调用。

5.8 本部分的分析原则

阅读二进制时，按以下顺序建立结论：

指令宽度
→ 数据来源
→ 扩展或截断方式
→ 运算与标志位
→ 参数位置
→ 返回值
→ 保存与后续分支

避免几个常见跳步：

  • 看见四字节就断定为有符号 int；
  • 看见方括号就断定一定访存；
  • 看见 cmp 就不区分有符号与无符号跳转；
  • 看见函数返回就认为调用者变量已经保存；
  • 看见程序没有崩溃就认定访问合法。

六、ELF、文件偏移与运行时地址

6.1 ELF 文件的基本结构

ELF 是 Linux 等系统使用的可执行与链接格式。它不只用于可执行程序，也用于：

  • 可重定位目标文件，例如 .o；
  • 共享库，例如 .so；
  • 某些核心转储文件。

分析 ELF 时，首先关注：

属性 要回答的问题
位宽 ELF32 还是 ELF64？
端序 多字节整数按小端还是大端解释？
机器类型 x86-64、ARM，还是其他架构？
文件类型 目标文件、可执行文件还是共享对象？
入口地址 装载后从哪里开始执行？
程序头 运行时如何建立映射？
节头 文件中各类代码与数据如何组织？

历史回顾命令：

file ./check
readelf -hW ./check
readelf -lW ./check
readelf -SW ./check
  • -h：查看 ELF 头。
  • -l：查看程序头。
  • -S：查看节头。
  • -W：使用宽输出，减少折行。

工具识别结果是分析起点，不等于已经理解程序行为。

6.2 节与段不是同一件事

节：偏向链接与文件组织

常见节：

节 常见内容
.text 机器指令
.rodata 只读常量、字符串
.data 有初始值的可写数据
.bss 需要零初始化但通常不在文件中逐字节保存的空间
.symtab 符号表
.dynsym 动态链接使用的符号
.rela.* 重定位信息

不能认为所有字符串一定在 .rodata，也不能认为所有代码只能出现在 .text。

段：偏向运行时装载

程序头描述装载需要的信息，其中 PT_LOAD 段决定哪些范围映射进内存，以及读、写、执行权限等属性。

一个段可以覆盖多个节。

因此：

节回答“文件如何组织”，段回答“运行时如何装载”。

运行程序并不要求装载器依靠所有节头逐节加载。

6.3 三种地址坐标

文件偏移

从文件开头计数的位置。

例如：

文件偏移 0x2004

表示文件开头之后的第 0x2004 字节位置。

ELF 虚拟地址

ELF 布局中使用的虚拟地址坐标，常出现在反汇编、符号及程序头信息中。

运行时地址

程序映射到某个进程后实际使用的地址。

三者可能数值相同，也可能不同。即使碰巧相同，也不能因此混淆概念。

6.4 根据 LOAD 段换算文件偏移

假设某个 LOAD 段具有：

  • 文件起点：$p_{\text{offset}}$；
  • ELF 虚拟地址起点：$p_{\text{vaddr}}$；
  • 文件数据大小：$p_{\text{filesz}}$；
  • 内存占用大小：$p_{\text{memsz}}$。

若目标 ELF 地址为 $V$，且位于该段的文件数据范围内：

$$ p_{\text{vaddr}}\leq V < p_{\text{vaddr}}+p_{\text{filesz}} $$

则对应文件偏移为：

$$ F=p_{\text{offset}}+(V-p_{\text{vaddr}}) $$

例如：

段的文件起点：0x2000
段的虚拟地址：0x3000
目标虚拟地址：0x3120

目标距离段起点：

$$ 0x3120-0x3000=0x120 $$

因此文件偏移：

$$ 0x2000+0x120=0x2120 $$

若地址只落在 p_memsz 覆盖、但超出 p_filesz 的范围，则可能属于零填充内存，没有对应的原始文件字节。

这也是为什么不能对 .bss 机械套用文件读取。

6.5 PIE、ASLR 与加载偏移

  • PIE：位置无关可执行文件的一种构建形式。
  • ASLR：运行时地址布局随机化机制。

PIE 使主程序能够在不同基址装载；ASLR 可以利用这种能力随机化位置。

但：

  • PIE 不等于每次运行地址一定不同；
  • 调试器设置和系统配置会影响随机化；
  • 非 PIE 程序的共享库、栈等位置也可能随机化。

对普通 PIE 映像，可以通过加载偏移 $B$ 关联：

$$ R=B+V $$

其中：

  • $V$：ELF 虚拟地址；
  • $R$：运行时地址；
  • $B$：该次装载的加载偏移。

这个公式不是文件偏移直接加基址。

七、符号、动态链接、PLT 与 GOT

7.1 符号的含义

符号把名称与某些程序实体关联起来，例如：

  • 函数；
  • 全局对象；
  • 尚需链接解析的外部引用。

保留符号时，工具可能直接显示：

main
check
strcmp

去符号后，内部函数可能只显示：

FUN_001011c9

但去符号并不等于所有名称全部消失。动态链接所需的某些导入符号仍可能存在。

没有函数名，不等于没有函数；有名字，也不等于名字一定可信。

7.2 外部函数的地址解析

程序调用：

strcmp(input, "cat");

实际 strcmp 位于 libc 中。程序构建时通常不把该共享库的最终运行地址写死。

动态链接过程需要将外部符号与实际地址关联。

一种常见调用路径：

程序中的调用指令
        ↓
PLT 跳板
        ↓
读取 GOT 槽中的地址
        ↓
跳到实际库函数
  • PLT：可执行跳板。
  • GOT：存放地址等数据的表。
  • 重定位信息：说明哪些位置需要按什么规则处理。

这是一种常见实现，不能推广为所有外部调用都必须经过同样的 PLT 路径。

7.3 重定位项中的 Offset

本例的 R_X86_64_JUMP_SLOT 项中，Offset 表示需要处理的目标虚拟地址。

例如：

0x3fd0 → strcmp

表示对应地址槽需要与 strcmp 关联，不是说该项必然位于文件偏移 0x3fd0。

字段含义必须结合 ELF 类型与上下文理解；不能看到英文“偏移”就统一当作文件偏移。

7.4 惰性绑定与立即绑定

惰性绑定

常见思路是：第一次调用某函数时才解析地址，之后复用解析结果。

立即绑定

在启动装载阶段完成相关函数地址解析，不等到首次调用。

本例执行过：

readelf -dW ./check | grep -E 'BIND_NOW|FLAGS'

显示：

FLAGS    BIND_NOW
FLAGS_1  NOW PIE

说明该程序要求立即绑定，并带有 PIE 标记。

因此：

看到 PLT 或解析跳板仍存在，不足以断定程序采用首次调用才解析。

7.5 立即绑定与 RELRO 不完全相同

RELRO 与装载后将某些重定位相关区域设为只读有关。

分析通常还要核对：

  • 是否存在 GNU_RELRO 段；
  • 哪些区域被覆盖；
  • 是否立即绑定；
  • 实际运行时权限。

常说的完整 RELRO 通常需要结合 RELRO 与立即绑定等条件判断。

本轮已证明 BIND_NOW，不能仅凭这一项宣称已经完整核验 RELRO。

八、GDB：从参数到返回值，再到分支

8.1 先确认调试现场

历史样本：

gdb ./check

进入后：

start
disassemble main

start 通常运行到 main 附近并暂停，便于建立现场。

若进程已经退出，读取寄存器可能出现：

No registers.

这通常意味着当前没有可读取的活动进程现场，不代表寄存器永久损坏。

应先确认进程状态，再重新启动或继续正确的调试流程。

8.2 三种断点写法

按函数名

break check

通常停在适合源码调试的位置，不保证就是函数入口第一条机器指令。

按函数内偏移

break *(main+112)

在明确计算出的指令地址设置断点。

这里：

112 = 0x70

不等于 0x112。

按绝对地址

break *0x6168e3b5626e

只适合这个地址在当前进程中仍然有效的情况。

重新运行、开启随机化或重新编译，都可能使旧地址失效。

8.3 函数调用前的检查要点

停在 call check 前：

x/i $pc
x/s $rdi

含义：

  • x/i $pc：按指令解释当前程序计数器所指位置。
  • x/s $rdi：将 rdi 指向的内存按终止零字符串显示。

历史截图确认：

当前指令：call check
第一个参数："car"

x/s 不是任意内存的通用查看方式。如果对象是含零字节的二进制数据，应按已知长度查看字节，例如：

x/16bx $rdi

这里表示查看16个字节，以十六进制显示。

8.4 si、ni 与 finish

命令 用途
si 指令级单步，可以进入被调用函数
ni 指令级跨过调用
finish 运行到当前函数返回

需要研究校验内部的数据变化时，使用 si 进入。

只想知道函数输入和最终输出时，可在调用点检查参数，再用 ni 跨过调用。

注意：跨过调用仍然会真正执行被调用函数；如果它等待输入或阻塞，调试器也要等待。

8.5 返回值已经产生，局部变量可能还没保存

调用附近：

call check
mov  DWORD PTR [rbp-0x34], eax

当暂停位置指向第二条指令时：

  • check 已返回；
  • eax 已有返回值；
  • 第二条 mov 尚未执行；
  • ok 对应栈槽尚未由该指令更新。

此时：

print /d $eax

比立即依赖局部变量 ok 更能直接说明返回值。

当前显示的指令通常是下一条待执行指令。

源码显示仍停留在：

int ok = check(input);

也不表示 check 尚未返回，因为同一行源码包含多条指令。

8.6 业务结果与退出码

本例正常读取输入后，不论匹配与否，最后都可以：

return 0;

所以必须分开看：

值 含义
strcmp 返回零 两个字符串相等
check 返回零 校验不通过
main 返回零 程序按正常路径结束

零没有脱离上下文的统一含义。

九、Ghidra：把反编译结果变成可靠结论

9.1 导入与自动分析

本轮已经在 Windows Ghidra 中导入 WSL 的 Linux ELF。

导入识别：

x86:LE:64:default:gcc

可以理解为：

  • x86 架构；
  • 小端；
  • 64位；
  • 相应默认语言配置；
  • GCC 编译器约定配置。

这个选择不是说“仅凭导入选项就证明了编译器版本”，具体编译信息还需其他证据。

Windows 上的静态分析工具可以分析 Linux ELF，不需要先转成 Windows PE。

9.2 PIE 文件与共享对象标识

PIE 可执行文件通常使用 ET_DYN 类型，与共享对象使用相同的 ELF 类型编号。

因此：

ELF File Type: shared object

不直接意味着文件是普通动态库。

应结合：

  • 解释器信息；
  • 入口；
  • 动态标志；
  • 程序结构；

共同判断。

本例还有已有的 PIE 标志作为补充证据。

9.3 常见导入提示

stdin 的复制重定位

摘要中出现：

R_X86_64_COPY
Runtime copy not supported

说明静态加载过程没有模拟这项运行时复制操作。

不能据此断言：

  • stdin 在真实运行时一定无效；
  • fgets 一定失败；
  • 程序无法执行。

此前 GDB 中已经成功读取输入，证明不能把导入提示等同运行故障。

libc 不在项目中

libc.so.6 -> not found in project

表示 Ghidra 项目没有额外导入该库的完整程序对象。

仍然可以利用外部符号分析：

puts
fgets
strcmp

不必为当前小样本导入整套 libc。

9.4 反编译不是恢复原始源码

反编译器根据指令、控制流、类型推断和已有符号，生成一种高级表示。

可能出现：

  • iVar1 等自动变量名；
  • 类型不完全准确；
  • 多余声明；
  • 不同的分支顺序；
  • 强制转换；
  • 多个原始变量合并；
  • 一个原始变量拆成多个临时值。

正确目标是恢复等价行为与约束，不是逐字复原源文件。

9.5 main 的业务流程

结合已知样本，可归纳为：

char input[32];


puts("请输入口令：");


if (fgets(input, sizeof input, stdin) == NULL) {
    return 1;
}


input[strcspn(input, "\n")] = ‘\0’;


int ok = check(input);


if (ok != 0) {
    puts("匹配");
}
else {
    puts("不匹配");
}


return 0;

这是便于理解的业务归纳，省略了编译器加入的栈保护等细节，不应当作反编译器逐字输出。

9.6 分支交换不等于逻辑改变

源码：

if (ok) {
    puts("匹配");
}
else {
    puts("不匹配");
}

伪代码：

if (value == 0) {
    puts("不匹配");
}
else {
    puts("匹配");
}

条件取反且分支交换后，行为仍然相同。

本例汇编：

cmp ..., 0
jz  不匹配路径

说明零走不匹配。

分析分支必须核对：

  1. 比较的真实值；
  2. 跳转条件；
  3. 目标基本块；
  4. 每条路径的输出或返回值。

9.7 变量重命名与语义判断

截图里它先后承担：

iVar2 = 1;             // 输入失败的退出状态
iVar2 = check(input);  // 校验返回值
iVar2 = 0;             // 正常退出状态
return iVar2;

全局重命名成 ok 会误导最后的返回含义。

重命名原则：

  • 先看变量的全部定义和使用；
  • 名称应描述整个生命周期中合理的角色；
  • 不确定时保留中性名称并添加注释；
  • 不为了“像源码”而强行命名。

9.8 字符串、交叉引用与调用关系

推荐路径：

成功/失败字符串
      ↓
使用它的指令
      ↓
输入输出函数
      ↓
校验函数
      ↓
参数、返回值与条件

交叉引用表示某个地址被引用，但不自动证明该路径会执行。

还需检查：

  • 引用是代码还是数据；
  • 数据是否真的被作为字符串使用；
  • 所在函数是否可达；
  • 是否只是无关提示或诱饵。

DAT_00102004 只是自动数据标签，不是错误标记。

本例中它对应 "cat"，可靠结论来自字符串内容、地址引用和传参数据流共同支持。

9.9 保存项目与修改程序

Ghidra 项目中的：

  • 函数命名；
  • 变量命名；
  • 注释；
  • 类型标注；

通常属于分析数据库内容。

保存这些分析信息，不等于直接改写原始 ELF。

指令修改、导出修改后的程序，则是另一类操作，必须单独确认。

十、编译器插入的保护代码与业务代码

10.1 栈金丝雀

本例出现：

mov rax, QWORD PTR fs:0x28

以及函数尾部的保护值比较和：

__stack_chk_fail();

在当前环境中，这些与栈保护有关。

基本思路：

  1. 进入函数时保存保护值；
  2. 返回前检查它是否变化；
  3. 不一致则进入失败处理。

它不是口令算法。

不能因此推断：

  • 所有函数都受保护；
  • 所有越界都会被发现；
  • 有金丝雀就不存在信息泄露；
  • 堆错误也会被它统一拦截。

10.2 in_FS_OFFSET 与线程局部存储

反编译器可能用：

in_FS_OFFSET

表达对 FS 相关存储的访问。

不能把它理解为源码中必然声明的普通业务变量。

同样，反编译出的保护值读取、比较和失败调用，应从口令业务逻辑中分离出来理解。

10.3 endbr64

endbr64 与间接分支跟踪相关。

看到该指令，只能说明程序包含相应入口指令。

是否在当前运行时真正执行完整的相关保护，还取决于硬件、系统和启用状态。不能仅凭一条指令就登记为“运行时保护已全面核验”。

十一、陌生 ELF 的独立分析方法

11.1 不依赖函数名的入口

去符号后，不一定有 main 或 check。

可从以下线索开始：

  • 输入函数；
  • 成功或失败输出；
  • 字符串引用；
  • 导入函数；
  • 入口与初始化流程；
  • 关键常量与循环。

函数名只是线索之一，不是唯一入口。

11.2 从输入建立数据流

要回答：

  1. 输入来自哪里？
  2. 缓冲区在哪里？
  3. 最大读取多少？
  4. 是否去换行或进行其他预处理？
  5. 传入哪个函数？
  6. 校验函数是否还读取全局数据？

不要默认“输入函数读到的内容”与“校验函数看到的内容”完全相同。

11.3 恢复循环与字节运算

后续更复杂样本常需要整理：

项目 记录内容
长度 精确相等、上限还是下限？
下标 从哪里开始，在哪里结束？
元素宽度 一字节、四字节还是其他？
扩展方式 零扩展还是符号扩展？
变换 加减、异或、移位、查表或重排？
比较 比较每个字节还是整体结果？
失败条件 哪一步直接退出？
成功条件 是否必须完成全部检查？

还原顺序与变换顺序通常相反，但要先判断变换是否可逆。

例如丢弃高位、掩码或查表可能造成信息丢失，不能见到运算就假设存在唯一逆运算。

11.4 正向验证与唯一性

得到候选输入后，必须重新代入全部条件。

需要区分：

  • 找到一个通过输入；
  • 找到所有通过输入；
  • 证明通过输入唯一。

程序输出一次 PASS，只能证明该输入在那次运行中通过，不自动证明唯一。
