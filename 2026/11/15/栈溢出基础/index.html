栈溢出基础

1. 栈溢出的本质

栈缓冲区溢出：向栈上的缓冲区写入数据，超出了该对象的边界。

不是“整个栈空间用完了”。

char buf[8];
read(0, buf, 12);
概念 本例含义
缓冲区容量 8 字节
读取上限 12 字节
实际读取量 看 read 返回值，不保证读满

只有实际写入超过 8 字节，这次才发生越界。

如果从数组中途写入，要计算剩余容量：

char buf[16];
read(0, buf + 12, 8);

从下标 12 开始只剩 4 字节；实际读满 8 字节，就越界 4 字节。

2. read 与字符串边界

ssize_t n = read(fd, buf, count);
  • fd：读取来源；0 表示标准输入。
  • buf：写入起点。
  • count：最多读取多少字节。
  • 返回值：实际读取量；0 表示输入结束，-1 表示出错。
  • 不检查目标数组容量，不自动补 \0。
情况 注意事项
键盘回车 通常会产生换行字节 0x0a
printf 'AAAA' 不自动输出换行
C 字符串 需要末尾的 \0
char buf[8] 最多容纳 7 个普通单字节字符和一个 \0
strcpy(buf, "ABCDEFGH") 实际需要 9 字节，包含结束符

2.1 越界写与越界读不同

char buf[8];
read(0, buf, 8);
printf("%s", buf);

即使恰好读入 8 字节、没有越界写，如果没有 \0，%s 仍可能继续读取数组外的内存，形成越界读。

3. 典型栈布局

以下仅适用于 x86-64、保留帧指针的典型示意，不是所有程序的固定布局。

高地址
┌────────────────────────┐
│ 保存的返回地址         │ ← rbp + 8
├────────────────────────┤
│ 保存的旧 rbp           │ ← rbp
├────────────────────────┤
│ 填充、其他变量、保护等 │
├────────────────────────┤
│ 局部缓冲区 buf         │
│ ↑ 从起点向高地址写入   │
└────────────────────────┘
低地址
  • 栈分配空间时，rsp 通常向低地址移动。
  • 数组从下标 0 连续写入时，向高地址推进。
  • 实际排列、填充、Canary 和偏移，都需要通过反汇编与调试确认。

4. 栈帧的建立与释放

4.1 典型函数序言

push rbp
mov  rbp, rsp
sub  rsp, 0x20
  1. 保存调用者的 rbp。
  2. 建立当前函数的帧指针。
  3. 预留 32 字节栈空间。

预留 32 字节，不代表源码一定有一个 32 字节数组。

4.2 典型函数尾声

leave
ret

leave 在这里相当于：

mov rsp, rbp
pop rbp
执行阶段 rsp 指向或发生的操作
执行完 mov rsp, rbp 保存的旧 rbp
执行完 pop rbp，即 leave 完成 保存的返回地址
执行 ret 取出返回地址并跳转，rsp 前进 8 字节

释放栈空间主要是移动指针，不是把原内存清零。

5. 覆盖对象不同，后果不同

被覆盖对象 可能的影响
局部变量 改变数值或判断条件
参数的实际存储位置 改变函数使用的数据
指针 后续访问错误位置
保存的旧 rbp 影响调用者后续栈访问或收尾
保存的返回地址 影响函数返回位置
  • i386 常见调用约定通常通过栈传参。
  • Linux x86-64 常见调用约定中，前几个整数或指针参数通常通过寄存器传递，也可能被编译器保存到栈上。
  • 源码里存在参数，不代表越界输入一定能覆盖到它。

发生溢出，不等于覆盖了返回地址。 覆盖返回地址，不等于成功控制程序。 程序没有崩溃，不等于没有溢出。

6. 从反汇编追踪输入位置

Linux x86-64 常见调用约定下，read 的前三个参数通过：

rdi：文件描述符
rsi：写入地址
rdx：读取上限

例如：

lea rsi, [rbp-0x20]
mov edx, 0x30
mov edi, 0
call read

表示从标准输入最多读 48 字节，写到 rbp-0x20 开始的位置。

6.1 lea 与 mov 的区别

lea rsi, [rbp-0x20]

计算地址，放入 rsi。

mov rsi, QWORD PTR [rbp-0x08]

读取该位置保存的 8 字节内容，放入 rsi。如果这里存的是指针，读出的内容也可以是缓冲区地址。

关键不是只看指令名，而是追踪最终 rsi 指向哪里。

7. 小端序与字节输入

整数 0x12345678 在小端内存中，按地址从低到高排列为：

78 56 34 12

发送原始字节：

printf 'AAAAAAAA\x78\x56\x34\x12' | ./over

不能把文本 '78 56 34 12' 当成这 4 个字节。

7.1 GDB 的两种显示方式

x/4bx 地址

可能显示：

0x63 0x61 0x61 0x61

而：

x/wx 地址

在小端环境中显示同一份数据：

0x61616163

8. 单字节越界的影响

off-by-one：边界计算差一，越界写入一个字节。

for (int i = 0; i <= 8; i++) {
    buf[i] = 'A';
}

对 8 字节数组来说，合法下标是 0～7，写入 buf[8] 已经越界。

一个字节也能改变整数的一部分：

原字节：78 56 34 12 → 0x12345678
改后：  00 56 34 12 → 0x12345600

危险程度取决于覆盖了什么以及后来怎样使用，不只取决于字节数量。

8.1 长度计算也可能出错

char buf[16];
size_t used = 20;
size_t remaining = sizeof(buf) - used;

size_t 是无符号类型，减法可能回绕为很大的正数。应先确认 used 不超过容量，再计算剩余长度；不能看到 sizeof 就认定安全。

9. 崩溃点不一定是根因

越界写入 → 数据被破坏 → 稍后使用坏数据 → 出错
   根因                                  暴露点

可能的表现：

  • 写入时就出错。
  • 使用坏指针时出错。
  • Canary 检查失败。
  • 函数返回时出错。
  • 完全不崩溃，但数据已经改变。

通过 read 向无效地址写入，也可能表现为错误返回或部分读取，不一定直接产生段错误。

9.1 排查原则

确认谁被改坏 → 找它何时改变 → 追查写入来源。

可在适当时机设置观察点：

watch -l p
continue

但 read 在内核中的写入不一定被直接捕获；比较输入前后的内存仍然重要。

10. 缓冲区容量与返回值

排查时同时记录缓冲区容量、传给读取函数的长度和实际读到的字节数。读取函数可能返回短读、文件结束或错误。把输入作为 C 字符串使用时，还要单独保证结尾的零字节有合法位置。

11. 识别越界写的起点

同一次越界写可能先破坏相邻局部变量，随后才影响返回过程。调试时可结合源代码和内存错误检测报告，优先定位第一次越界访问，再核对长度变量的来源和类型转换。

12. 区分容量、有效数据长度与字符串长度

例如，一个 16 字节缓冲区接收 8 字节二进制数据时，容量是 16，有效长度是 8。若要把这 8 字节当作 C 字符串，必须确认其中没有提前出现的零字节，并在可用空间内补上终止零。若收到 16 字节，缓冲区已满，不能再追加一个字节。

13. 长度错误是怎样产生的

情况 容易漏掉的检查
输入带终止符 容量要包含终止符
多次追加 检查剩余容量
读取返回负值 先处理错误，再转换为无符号长度
长度单位不同 分清字节数和元素数

例如按元素计数的数组在传给按字节计数的接口时，需要核对元素大小与总容量。

14. 崩溃现象与根因

相邻变量被覆盖、地址失效和函数返回异常都可能来自同一次越界写。崩溃现场适合判断最后发生了什么。定位根因时，应回到首次非法写入，核对目标对象、写入范围和长度的来源。验证修复时可以覆盖空输入、刚好装满和超出容量三类边界。
