周报：ROP 系列 · 格式化字符串

本周期整理五块知识：ret2libc、简单 ROP、坏字符与受限输入、栈迁移与两阶段链、格式化字符串。
下面的偏移、地址、参数位置、libc 偏移都是示意值，实际做题必须按当前二进制重新测量；整理知识不等于已经掌握，实操状态在文末单独标注。

学了什么：

一、ROP 系列

1. ret2libc

1. 为什么需要它（原理）

栈溢出能让我们控制返回地址，但只能跳到程序里已有的代码。如果程序里既没有 win 函数、也没有 "/bin/sh" 字符串，怎么办？

答案是去 libc 里借：libc（C 标准库）几乎一定包含 system 函数和 "/bin/sh" 字符串。把返回地址改成 system，再按调用约定给它传 "/bin/sh" 的地址，就能执行 system("/bin/sh") 拿到 shell。

唯一的障碍是 ASLR：libc 每次装载的基址都不同，system 的真实地址不能写死。所以 ret2libc 的核心就一句话：

先泄露 libc 的运行时地址，算出基址，再调用 libc 里的函数。

2. 五步路线
步骤 要解决的问题 关键操作
① 已有函数可调用 libc 里有 system，但地址随机 通过 PLT/GOT 找到它的运行时地址
② 字符串位置 system 需要一个指向字符串的地址 用 libc 里的 /bin/sh，或先写入内存
③ 真实地址泄露 ASLR 下 libc 地址每次不同 泄露一个已知符号的 GOT 项
④ 计算基址 由泄露值反推 libc 装载基址 base = leak(symbol) - offset(symbol)
⑤ 两阶段利用 一次溢出不够完成全部动作 先泄露并跳回 main，再发第二次载荷
3. 必须分清的三个概念

（1）字符串内容 vs 字符串地址

"flag" 是内容；传给 system 的是指向这串字节的地址（一个指针）。很多人把“字符串”和“字符串的地址”混为一谈——system 要的是后者。

（2）PLT vs GOT

PLT（过程链接表） GOT（全局偏移表）
是什么 代码，可执行、可跳转 数据，存函数真实运行时地址
例子 system@plt 是固定可调用入口 system@got 里存的是地址值
用法 调用 puts@plt = 执行 puts 代码 读 puts@got = 读出 puts 在内存里的真实地址

（3）泄露“谁的地址”与“用哪份 libc 算偏移”必须一致

泄露 puts 的 GOT，就必须用同一份 libc 里 puts 的符号偏移去算基址。乱配符号或版本，基址就错。

6. 易错点
  • 泄露字节不完整：printf 遇到 \x00 可能停、puts 只打印到换行，收泄露值要按实际边界补齐 8 字节。
  • 空字节截断：地址里含 \x00 时，用 send/sendline 的接收逻辑要留意。
  • 栈对齐：进入 system 前栈末位要满足 16 字节对齐，否则 movaps 崩溃，常通过补一个 ret 调整（不是每次都要补）。

  • 两阶段要跳回可再次输入的位置：跳到 main（或 vuln 函数）而不是随便一个地址。

2. 简单 ROP

1. gadget 是什么

以控制转移指令（通常是 ret）结尾的短指令序列，例如 pop rdi; ret：先弹出栈顶值到 rdi，再 ret 跳到栈上的下一个地址。

ROP 的本质：程序里没有现成的 system(addr) 完整调用，但散落着零碎指令，我们用 ret 把零碎指令串起来，拼出“设参数 + 调函数”的效果。

2. 参数怎么传（x86-64 调用约定）
  • 第 1 个参数：rdi；第 2 个：rsi；第 3 个：rdx；再往后 rcx / r8 / r9。
  • 所以要调 system(addr)：找 pop rdi; ret。
  • 调三参数函数：依次 pop rdi; pop rsi; pop rdx; ret，或分段拼。
3. 链是怎么走起来的（关键心智模型）

每个 ret 弹出栈顶作为下一个执行地址，rsp 随之 +8。所以链的本质是在栈上按顺序摆地址：

连续调用：把前一个函数的返回地址写成下一段参数 gadget。前一个函数返回后，rsp 正好落在那段 gadget 上，继续弹参数、再 ret 到下一个函数——链式串起多次调用。

4. 每个 gadget 的副作用要逐条核对
  • 有的 gadget 是 pop rdi; pop rbp; ret——多弹一个寄存器，栈上就要多放一个占位值，否则后面偏移全错。
  • 有的 gadget 除了 pop 还改别的寄存器，可能破坏后续调用需要的值。
  • 要核对：动了哪些寄存器、动了哪些内存、rsp 移动了多少。
5. 写内存（write4 类）

没有现成字符串时，用写内存 gadget 把字符串写进可写区（如 .bss、.data），再传它的地址。常见形式是 mov [reg1], reg2; ret，需要再找 pop reg1; ret 和 pop reg2; ret 先把地址和数据分别装进去。

7. 易错点
  • PIE 下地址是偏移：ROPgadget 给的是文件内偏移，运行时要加基址。
  • movaps 崩溃：先查是不是对齐问题，再决定补 ret，别当万能补丁。
  • 输入长度限制：链太长会被截断，要数清总字节数。
  • 搜索命中要反汇编核对：ROPgadget 命中的字节可能从非预期位置开始，disasm 确认后再用。
  • 额外 pop 破坏：漏掉占位值会让寄存器错位。

3. 坏字符与受限输入

1. 先分清“哪里坏”
情况 表现
截断 输入到某个字节就停（如 strcpy 遇 \x00）
替换 某字节被改成别的值
拒绝 含某字节直接退出
写入后被修改 字节进了内存，程序随后又改动了它

定位方法：把“发送的字节”和“内存里实际出现的字节”逐字节对照，找到最早变化的位置。

2. 谁可能含坏字符

载荷里所有字节都要查，不只是数据：

  • gadget / 函数地址本身
  • 目标地址（如字符串存放处）
  • 编码后的数据
  • 填充 b'A' * offset

只要其中一处含受限字节，整条链就失效。

3. 常用解法：编码 + 运行时解码

坏字符只影响数据（如 "flag.txt"）时：

  1. 用一个坏字符集合外的 key 对数据做 XOR 编码。
  2. 链里先写“编码后的数据”到内存（编码字节都合法）。
  3. 再找一段能做 XOR 解码的 gadget，运行时把它还原成目标字符串。
  4. 最后把字符串地址传给 system / print_file。

本质：写入时规避坏字符，运行时用 gadget 恢复。

4. 受限 gadget（fluff 类）

当常用 gadget 很少时：

  • 给每段候选指令写清楚前置条件和后置状态（进来时寄存器/内存是什么、出去后变成什么）。
  • 组合多段“非直观”指令片段拼出所需的写内存能力，而不是指望一段现成的 mov [x], y; ret。
5. 易错点
  • 只编码字符串、忘了编码地址：地址字节也可能含坏字符。
  • 编码 key 不能落在坏字符集合里，否则编码结果仍含坏字符。
  • 注意 gadget 的额外副作用（破坏的寄存器、rsp 变化、是否修改内存），会干扰后续链。

4. 栈迁移与两阶段链

1. 为什么需要它（原理）
  • 溢出长度不够：输入预算小，覆盖不到足够长的返回地址链。
  • 需要的 ROP 链太长，当前栈帧放不下。
  • 解决：把 rsp 迁移到一块我们可控、且长度足够的内存（如 .bss 段预写入的数据），在那上面执行完整链。
2. leave; ret 的机制

leave 等价于两条指令：

所以 leave; ret 整体是：rsp 指到当前栈帧底 → pop rbp 把保存的旧 rbp 弹回 rbp（rsp+8）→ ret 弹出栈顶作为返回地址（rsp+8）。

关键：只要控制住“保存的 rbp”和“返回地址”两个值，就能让 rsp 跳到任意位置。

3. 迁移怎么发生（两次 leave; ret）

旧栈帧布局（低地址 → 高地址）：

溢出时：padding 填满局部变量；用新栈地址覆盖“保存的 rbp”；用 leave; ret 地址覆盖“返回地址”。

  1. 第一次 leave; ret：rsp 指到旧 rbp → pop rbp 把伪造的新栈地址弹进 rbp → ret 跳到下一段 leave; ret。
  2. 第二次 leave; ret：此时 rbp 已是新栈地址 → mov rsp, rbp 把 rsp 迁到新栈 → pop rbp 弹出新栈第一个槽（占位）→ ret 跳到新栈上的第一个 gadget。

结果：rsp 从旧栈迁到可控内存，链在新栈上继续走。

第一个槽是占位，真正的链从 新栈 + 8 开始。

5. ROP 数据与执行权限的区分
  • 新栈（如 .bss）必须可写（预写入数据），但不要求可执行。
  • 迁移只是让 rsp 指向那里读数据，真正执行的仍是程序里原有的可执行 gadget。
  • 别把“可写的数据区”误当成“可执行的代码区”。
6. 迁移后栈对齐

进入函数（如 system）前，rsp 仍要满足 16 字节对齐；迁移后要重新数清 rsp 的位置，不能沿用迁移前的对齐结论。

7. 两阶段链
  • 第一阶段：迁移前的准备（泄露地址、把长链预写入目标内存）。
  • 第二阶段：触发迁移，在可控内存上执行完整链。
  • 常见模式：先 read/gets 把数据读到 .bss，再迁移过去执行。
8. 易错点
  • 伪造 rbp 的值按 leave 流程推演：mov rsp, rbp 直接把 rsp 设为 rbp，所以覆盖保存 rbp 的值通常就是新栈地址。
  • 新栈第一个槽是占位，漏掉会让链错位。
  • 迁移目标必须可写且数据已实际写入，否则读到垃圾。
  • 迁移后对齐要重新推演，不能沿用旧栈的对齐。

二、格式化字符串

1. 漏洞根源

  • printf("%s", buf)：安全，buf 只当数据。
  • printf(buf)：危险，buf 里的内容会被当成格式串解释。用户输入含 % 时，就能读栈上数据甚至写内存。

2. 两种原语

原语 手段 效果
读取（泄露） %p、%x、%s、%n$x 读栈上/寄存器里的值，或按地址读内存
写入 %n / %hn / %hhn 把“已输出字符数”写到某个地址指向的位置
  • %p 只是观察；%s 会解引用（把值当地址去读），配合可控地址可读任意内存。
  • %n 写入的不是参数值，而是到它为止 printf 已输出的字符总数。%hn 写 2 字节、%hhn 写 1 字节。

3. 参数位置（x86-64 最易错点）

  • 前 6 个参数在寄存器：rdi, rsi, rdx, rcx, r8, r9。
  • 格式串本身是 rdi（第 1 个参数）。
  • 所以 %1$p 对应 rsi（第 2 个参数），%6$p 是 r9，栈上第一个参数从 %7$p 开始。

定位可控输入：反复打印 %i$p，找到哪一位的值正好等于自己输入的字节，那个偏移就是输入在参数里的位置。地址放进输入时，要落在 8 的倍数偏移上，否则取参错位。

4. 分段写入

  • 写入宽度与取模：
指令 写字节数 取模
%n 4 mod $2^{32}$
%hn 2 mod $2^{16}$（65536）
%hhn 1 mod $2^{8}$（256）

实际写入 = 已输出计数 mod 写入宽度。例：计数 260，%hhn 写入 $260 \bmod 256 = 4$。

  • 多次写入顺序：printf 计数只增不减，要写多个不同字节值，按目标字节值从小到大依次写；每次多输出的字符数 = 目标值 − 当前计数。
  • 回绕：目标字节值比当前计数小时，补 255，不是 256（补 256 会 mod 256 绕回原值，等于没变）。
  • 输入长度限制：分段写要输出大量空白凑计数，自动生成器可能产生 1KB+ 载荷，留意输入预算。
  • 小端：字节值的顺序 ≠ 地址顺序。写 0x01020304 时低字节 04 在低地址，内存里是 04 03 02 01。

5. 稳定泄露（第 11 节核心）

  • canary 三特征：① 低字节恒 00（防字符串读越界把 canary 带出）；② 每次进程启动重新随机；③ %p 按值打印不受 \0 影响，可直接泄露。
  • 三地址黄金组合：
泄露目标 用途
canary 绕过栈保护
main 返回地址 算 libc 基址
程序代码地址 算 PIE 基址
  • ASLR 与「基址 + 偏移」：ASLR 每次随机化的是基址，基址页对齐（低 12 位 = 000），页内偏移固定。真实地址 = 基址 + 偏移，基址 = 泄露地址 − 偏移。
  • 完整偏移 ≠ 低 12 位：泄露地址的低 12 位只是页内部分；算基址要用符号的完整偏移（如 0x2a601），不能只拿低 12 位（0x601）。
  • 泄露时注意输出边界、地址宽度与空字节截断。

6. 目标可写性与 RELRO

写目标前先判断是否可写：栈 / 全局变量（.bss/.data）可写；GOT 可写性看 RELRO。

RELRO 级别 GOT 状态 能否 GOT 覆写
无 / Partial RELRO 可写 能（如把 printf@got 改成 system）
Full RELRO 只读 不能，换思路

7. 自动生成

用 fmtstr_payload 前必须先确定 offset；自动生成前先手动做一个小例子，不要当黑盒。

8. 易错点

  • 32 位示例不能照搬到 64 位：参数编号、寄存器都不一样。
  • 目标地址要放在对齐好、能稳定命中的位置，别让它先被 %s 之类解引用炸掉。
  • 输出计数是累计的，分段写时先算清每段要多输出多少字符；回绕补 255 不补 256。
  • 硬编码目标地址会因 PIE/ASLR 失效，用同一进程泄露的地址。
  • 不能把所有目标都换成 GOT（Full RELRO 下不可写）。

实操时每道题的固定流程

  1. 确认来源、架构、附件与运行方式。
  2. checksec 检查保护，确认输入输出。
  3. 找到输入点、长度与漏洞条件。
  4. 画出与利用相关的内存布局。
  5. 用 cyclic 与调试器验证偏移和可控范围。
  6. 列出利用条件：目标地址、参数、权限、泄露、输入预算。
  7. 写最小 exp，在关键位置下断点。
  8. 本地稳定复现，再检查远程环境（libc 是否一致、装载环境、输入长度、换行）。
  9. 记录结果，隔一段时间从空白重写验证。
