学习笔记：Pwn 工具与保护机制

一、Pwn 工具上手

1.1 IDA 静态分析

在 Windows 的 IDA 里打开与 WSL 调试时相同的 ELF，等自动分析完成。函数列表适合找 main 和有名字的函数，字符串列表适合从提示或错误消息切入。图形汇编适合追踪分支，线性汇编适合核对地址和相邻指令，伪代码适合先读整体逻辑。

快捷键用法
Shift+F3 / Shift+F12打开函数列表 / 字符串列表
Space / F5 / Tab切换图形与线性汇编 / 反编译当前函数 / 在汇编和伪代码间切换
G / Esc / 双击操作数跳到地址或名称 / 返回上一处 / 跟到定义或目标
X查看选中地址或标签的交叉引用，反查哪些代码引用它
Alt+T / Ctrl+T搜索显示文本 / 查找下一处
N / Y重命名 / 编辑类型
: / ;添加普通注释 / 可重复注释

从字符串追到分支。在字符串列表找到 Correct，双击跳到数据，选中标签按 X，再跳到引用它的指令。找到附近的 puts 后，沿图形视图的入边往回找，确认哪个条件会进入成功块。查输入点也可以从 fgets 等导入函数的交叉引用出发，回到调用处核对缓冲区和长度参数。

用汇编核对伪代码。在 Linux x86-64 下，strcmp 的前两个参数在 rdi、rsi，返回值在 eax。相等时返回 0，随后 test eax,eax 会设置 ZF。看到 je 时还要跟到目标块，确认它通往成功还是失败。指针类型也要核对。若 int 占 4 字节，input[2] 在 int * 上对应 8 字节偏移。movzx eax, byte ptr [rax] 只表明这条指令读了 1 字节。

与 GDB 对照。IDA 用于定位代码，GDB 用于验证实际执行。两边绝对地址不同时，先确认是同一份 ELF，再比对函数内偏移和机器码。例如原练习中 charcheck+0x93 处是 cmp cl, al，重新编译后以实际指令为准。命名和注释通过保存 IDA 数据库保留。

1.2 pwntools

from pwn import ELF, context

elf = ELF("/bin/cat", checksec=False)
context.binary = elf
print(context.arch, context.bits, context.endian)

ELF() 解析程序文件。context.binary 根据文件设置架构、位宽和字节序。练习中读到 amd64、64、little，所以完整地址用 p64() 打包。

1.2.1 环境和运行位置

cd ~/pwn-practice
source .venv/bin/activate
python3 -c "from pwn import process; print('OK')"

在 WSL 普通命令行执行 Shell 命令。出现 pwntools 的交互提示时，输入会发给被调试的程序。新开终端时，可以重新激活 .venv。

1.2.2 按提示收发数据

from pwn import process

io = process(["python3", "echo_lab.py"])
io.sendlineafter(b"nickname> ", b"Alice")
io.sendlineafter(b"city> ", b"Shanghai")
print(io.recvline())
io.close()
方法用途
process() / remote(host, port)启动本地进程或连接网络服务。两者都提供相同的基础收发方法。
recvuntil() / recvline()读到指定字节或读到换行。提示里的空格也参与匹配。
send() / sendline()原样发送或在末尾追加换行。
sendlineafter()先按提示读取，再发送一行。
interactive() / close()把后续输入交给键盘或关闭通信。

交互卡住时，用 context.log_level = "debug" 查看实际收发。目标若在等输入结束，单独发送 b"\n" 可以验证它是否缺少换行。b'\n' 是一个空行，接收超时返回的 b'' 则没有字节。

收发是按字节推进的

把本地进程和 TCP 服务都看成两条字节流，一条发送，一条接收。一次 send 和一次 recv 并没有固定的一一对应关系。recvuntil 按提示分界，recvline 按换行分界，recv(n) 最多取 n 个字节。脚本和目标互相等待时，先看双方各在等哪个分隔符。sendlineafter 只是等待和发送的组合，定位问题时可以拆开观察。

位宽和字节序

p32() 和 p64() 分别把整数打包成 4 字节和 8 字节。u32() 和 u64() 做反向转换。小端让低位字节排在前面，p32(0x123456, endian="little") 的结果是 56 34 12 00。用 .hex(" ") 查看字节，用 io.send(data) 发送原始数据。

构造和反查偏移

from pwn import cyclic, cyclic_find, flat

pattern = cyclic(24, n=4)
piece = pattern[9:13]             # b'aaad'
offset = cyclic_find(piece, n=4)  # 9
data = flat({offset: b"TEST"}, filler=b"A")
print(data)                       # b'AAAAAAAAATEST'
print(len(data))                  # 13

偏移从 0 数起。偏移 9 前有 9 个填充字节，TEST 再占 4 字节。flat() 可用 word_size 和 endianness 指定整数打包方式，length 指总长度。生成和查找 cyclic 模式时使用相同的 n 和字母表。

字节宽度、字节序和偏移各管一件事

位宽决定打包占多少字节，字节序决定这些字节怎么排列，偏移决定从数据开头数多少字节开始放。以 0x123456 为例，p32 的小端结果是 56 34 12 00。它放在偏移 9 时占用索引 9 到 12，可以用 data[9:13] 取回。cyclic 的 n 指定位片段的长度，和目标指针宽度是两个概念。以 n=4 生成的模式中，可以用任意连续四字节定位，包括跨过四字节分组边界的片段。

查询结果
elf.symbols.get(name)符号地址。导入函数的符号可能由 pwntools 根据 PLT 或 GOT 补充。
elf.plt.get(name)程序内调用外部函数的代码入口。
elf.got.get(name)存放指针的槽位地址。运行后用 GDB 的 x/gx 读取槽位内容。

.get() 查不到时返回 None。如果 symbols 和 GOT 相同，结合 PLT 输出判断这个值实际指向的位置。

从脚本启动调试或附加进程

gdb.debug() 在调试器下启动新进程，gdb.attach() 附加到已有进程。练习中前者成功，后者曾超时。tmux 用来分屏，Ctrl+B 后按方向键可切换窗格。

1.3 GDB / Pwndbg

命令用途
starti / start停在启动的第一条指令，或尝试停在 main。动态链接程序执行 starti 后可能停在 ld-linux。
context / telescope $rsp 8查看寄存器、反汇编和栈，或从栈顶查看 8 个位置并跟踪指针。
vmmap看映射范围、权限和所属模块。地址归属按 Start ≤ 地址 < End 判断。
x/2i 地址 / x/gx 地址反汇编两条指令，或读取 8 字节并用十六进制显示。

1.4 ROPgadget

搜索并核对指令

ROPgadget --binary /bin/cat --only 'pop|ret'

vmmap cat
x/2i (0x555555554000 + 0x43edee)

上例使用该次运行的 cat 基址，算得 0x555555992dee。Pwndbg 显示 rex.WB pop r11 和 ret。两条指令共让 rsp 前进 16 字节。若看到 pop qword ptr [rax]，还要记录它会写入 rax 指向的内存。

文件地址、模块基址与运行时地址

ELF 里的符号地址和 ROPgadget 的结果来自文件视角。换算运行时地址时，先识别地址所属模块，再求该地址相对模块的偏移，最后加上本次运行的模块基址。对实验里的 cat，ELF 映像从虚拟地址 0 布局，所以可以直接用 gadget 的值作为偏移。vmmap 的 Offset 是映射对应的文件偏移，Perm 是运行时页权限。用地址找映射时包含 Start，排除 End。

看懂间接调用与指令副作用

PLT 是调用外部函数时可以经过的一段代码，GOT 是存放解析结果的槽位。查 GOT 时分开记录槽位地址和槽位内容，前者决定去哪里看权限，后者决定指向哪里的代码。检查 gadget 时，同样要逐条记录效果。pop r11 改写寄存器，pop qword ptr [rax] 写入内存，ret 从栈上取下一条指令的地址。普通 x86-64 的两个 pop 加一个 ret 会让 rsp 前进 24 字节。

二、保护机制

用 checksec 查看文件属性

在 WSL 普通命令行运行 pwn checksec /bin/cat。Arch 给出架构、位宽和字节序。Canary、NX、PIE 和 RELRO 提供文件级线索，分别用反汇编或运行时映射核对。下面按 Canary、NX、PIE、ASLR、RELRO 的顺序展开。ASLR 的实际效果可比较多次运行的映射。

1. Canary 检查的是栈帧里的保护值

进入受保护的函数时，编译器生成的代码把保护值复制到栈帧中。退出前再比较。如果两者不一致，程序会走向 __stack_chk_fail。在本次 canary_on 的 main 中，入口从 fs:0x28 取值并写到 [rbp-0x8]，结尾用 sub 比较并用 je 选择正常返回路径。分析一个写入时，要看具体函数有没有这段检查，写入是否经过保护值，以及检查何时执行。Canary found 是文件级线索，具体函数以反汇编为准。实验中的 fgets 在两个版本里都限制输入长度。

2. NX 检查的是取指位置的页权限

内存页的读、写、执行权限分别表示可以读取内容、修改内容和从这里取指令。栈处于 rw-p 时，程序仍然可以写栈，已有的越界写也仍可能发生。CPU 尝试从该页取指时才受到执行权限限制。分析时先定位字节所在页，再看有没有 x。checksec 根据文件属性给出静态判断，vmmap 能确认本次实际权限。

3. PIE

PIE 让主程序可以加载到不同基址。同一文件中，函数和 gadget 的模块内偏移保持固定。用本次主程序基址加偏移可得运行时地址。

4. ASLR

ASLR 影响每次启动时主程序、共享库和栈放在哪里。关掉主程序 PIE 后，实验中的主程序两次都在 0x400000，libc 和栈仍然变动。计算地址时，先确定属于哪个模块。已知运行时地址和同一文件中的相对偏移，可以相减得到该模块的基址。GDB 的 disable-randomization 设置也会影响观察结果，off 表示让新启动的进程采用系统随机化设置。

5. RELRO 限制重定位相关页的写权限

动态链接器需要把外部符号解析成实际地址，并填入相应槽位。Partial RELRO 保护部分重定位区域，采用延迟绑定的 PLT 槽位通常仍需可写。Full RELRO 配合启动时绑定，填好后把受保护的页设为只读。实验中 Partial 的 puts 槽位在首次调用前指向主程序内的延迟绑定代码，Full 的槽位在 main 开始时已经指向 libc。只读页仍可以读取槽位。判断能否写时，查的是槽位地址所在页，而不是槽位里的目标地址。

用 pwn checksec 文件 查文件属性，用 vmmap 核对运行时权限，用反汇编确认保护代码何时执行。

机制分析时看什么实验记录
Canary具体函数是否保存并检查栈上的保护值。检查发生在返回前。canary_on 从 fs:0x28 取值并存入 [rbp-0x8]。返回前比较，失败时调用 __stack_chk_fail。canary_off 无这两段。两份程序均用 fgets 限制写入长度。
NX目标内存页有没有 x。栈可写时，越界写仍可能发生。stack_nx 的 [stack] 为 rw-p，stack_exec 为 rwxp。
PIE主程序能否换基址。计算运行时地址时区分模块基址和模块内偏移。开启地址随机化后，同一 PIE 文件重启时基址改变。
ASLR每次运行中主程序、库和栈实际映射到哪里。stack_nopie 两次均在 0x400000，libc 和栈仍会变化。GDB 可用 show disable-randomization 查看调试设置。
RELROGOT 槽位所在页有没有 w，以及槽位中的指针何时完成绑定。Partial 版的 puts 槽位 0x404000 在 rw-p 页。Full 版槽位 0x403fe0 在 r--p 页，x/gx 仍能读出指向 libc 的值。

对照实验每次只改变一个保护选项。比较地址前先确认模块和本次运行的映射。比较 GOT 时，槽位地址用来查页权限，读出的槽位内容用来判断它指向哪个模块。
